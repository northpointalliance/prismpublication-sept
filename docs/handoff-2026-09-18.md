## What actually happened today, in order

1. **Brand-safety copy reordered.** "We reject copy that impersonates the assistant, and we reject weapons, explosives, and political campaigning" had the wrong priority, listing impersonation before the genuinely dangerous categories. Reordered everywhere it appears (`/ad-submission/`, `/terms/`, homepage, the actual screening system prompt in `screening.js`). Also caught `mem/current.md` incorrectly grouping gambling into the "blocks outright" list, it never blocks, it always routes to manual review.
2. **Dropped an unverifiable "categories we see most" claim**, duplicated on two pages, a leftover from the old fixed-niche build with no traffic data behind it now that categories are open.
3. **Homepage developer/SDK framing removed**, see above. Title, JSON-LD, H1, hero, a highlights card, and a full section were still developer-pitch language after the repositioning was supposedly already done. Fixed, and flagged in memory that a future copy sweep should specifically re-check those exact spots rather than assume an earlier pass covered them.
4. **The live chat was fabricating answers about itself.** Daniel tested it on his phone: asked if questions are stored, got "no, not stored," directly contradicting the privacy text on the same page. Also claimed to be a custom-trained model (false, off-the-shelf Workers AI/OpenAI under a system prompt), invented a subscription business model (real one is free submission + prepaid click), and denied ads exist at all. Root cause: the system prompt had zero grounding in the site's own facts. Fixed in `_lib/answer.js`: a numbered ground-truth block (data is stored, not custom-trained, real business model, ads can be truthfully confirmed to exist though never recommended by name), plus a fifth fact for "who built this" (Daniel's exact wording, only if asked directly, never volunteered).
5. **"Ask anything" was too open an invitation, and the chat had no actual content boundary.** The system prompt literally said "answer whatever the visitor asks, on any topic" with no guardrail beyond medical/legal/financial advice, on a general-audience site with no age gate. Swept "ask anything" copy off `/run-ads/` and the homepage, replaced with "ask a real question." Added an explicit rule: never produce sexual/explicit content, anything sexualizing minors, violence/weapons/illegal-act instructions, decline in one sentence and move on.
6. **Advertiser-set budget, real number.** Daniel confirmed a $5.00 minimum spend directly, and that advertisers should set their own budget rather than pick from fixed packs. `CREDIT_PACKS_CENTS` replaced with `MIN_CREDIT_PURCHASE_CENTS`/`MAX_CREDIT_PURCHASE_CENTS` in `pricing.js`; `/campaign/:token` now has a plain amount input instead of three buttons. A real, visible "Frequently asked questions" section was added to `/ad-submission/` explaining pay-per-click plainly, including why it's not priced per 1,000 impressions (CPM), at Daniel's explicit request.
7. **Click-fraud guard, a real gap closed.** `functions/c/[id].js` billed any bare GET request with zero verification, curl, a scraper, a guessed ad id, all would drain an advertiser's credit. Now a click only bills if it traces to a genuine prior `/api/chat` match for that exact session, and a session can only bill one click per ad ever. Doesn't stop a scripted attacker running real chat turns through fresh session IDs; `chat.js`'s existing per-IP rate limits are what bounds that, no automated alerting yet.
8. **`draft-ad.js` was crashing into a useless generic error, twice diagnosed.** Daniel reported "Could not reach the ad builder" on a real product URL. First fix (an unguarded D1 call) turned out not to be the actual cause, confirmed by checking `chat_events` directly and seeing the D1 write succeed both before and after that fix. The real gap: `_lib/model.js`'s AI completion call had no timeout at all, unlike the page fetch, so a hang there got killed by Cloudflare outside any try/catch, producing a non-JSON response. Fixed with a 15s bound on both the OpenAI and Workers AI paths, a general fix for every caller of `complete()`, not just the ad builder.
9. **A house-ad admin feature, and a cross-business integration.** Daniel owns a second site, devorahsart.com (his daughter's art), same Cloudflare account, and didn't want to buy PayPal credit from himself to list it. Built a real, repeatable "Go live free (house ad)" action in `/admin/` (not a one-off DB hack), then used it to list all 15 real products from devorahsart.com's actual catalog as house-ad campaigns, pulled from that site's own `data/products.json` via a separate repo clone, not AI-drafted copy. Full detail: `mem/current.md`'s house-ads section. This also surfaced and fixed a real bug on devorahsart.com itself (wrong PayPal business email on every buy button, documented in that repo's own `mem/current.md`, out of scope for this repo beyond the cross-listing).

## Guardrails that exist for a reason -- read before you "fix" something

- **Visual identity is frozen** (background color, font choice, base font sizes), copy and structure are not, see the FROZEN section above and in `mem/current.md`. Don't conflate the two.
- **No `—` or `" -- "` in visible public-page copy.** Confirmed and swept repeatedly this session; grep before shipping copy changes. Internal docs (this file included) are exempt.
- **Don't invent numbers, conditions, or business facts.** Came up hard again today: the chat fabricating its own business model, and the "categories we see most" claim with no data behind it. If you don't know the real answer, say so and ask.
- **Don't fabricate data when real data exists to pull instead.** The devorahsart cross-listing was built from that site's actual `data/products.json`, fetched via a real repo clone, specifically because Daniel rejected AI-drafted copy for a case where real copy already existed. Default to finding the real source before drafting a substitute.
